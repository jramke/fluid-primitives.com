The day/month/year cells themselves are built entirely client-side (no Fluid template exists for `tableCell`/`tableCellTrigger` - see the DatePicker docs page's "Client-rendered grid" note), so their styling lives here as descendant selectors on this shared `` wrapper instead of on a `class="{ui:cn(...)}"` prop the cells themselves could carry. Zag spreads one generic `tableCellTrigger`/`tableCell` anatomy part for day/month/year alike - the rendered `data-part` is always `table-cell-trigger`/`table-cell`, never `day-table-cell-trigger` or similar. Only `data-view` ("day"/"month"/"year") tells the cells apart, so every selector below pairs `[data-part=table-cell-trigger]` with `[data-view=...]` rather than a per-view part name.
